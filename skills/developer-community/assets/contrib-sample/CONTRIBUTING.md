# Contributing

Contributions are welcome. New contributors: look for issues labeled `good first issue` for first-timer-sized work. Existing contributors: help triage open issues to keep the backlog fresh.

## Setup

Run `make setup` once, then `make test` to verify your environment before starting. CI runs the same checks.

## Finding work

- New contributors: start with issues labeled `good first issue`.
- Every issue should state its scope, acceptance criteria, and how to test. If an issue does not, ask on the issue before starting.
- Existing contributors: pick up triaged issues in your area.

## Making a change

1. Create a branch from `main`.
2. Make your change and add tests.
3. Run `make test` locally until green.
4. Open a pull request; CI runs the same checks.

## Review

Maintainers review pull requests; first responses usually land within a few days. Disagreements are resolved by the maintainer council.

## Recognition

Contributors — code and non-code — are thanked in release notes and listed on the contributors page. Non-code contributions (triage, docs, testing, design, support) count toward the contributor ladder.

## More involvement

Reviewers are promoted from active contributors. See GOVERNANCE.md for how decisions are made and how outsiders gain responsibility.
