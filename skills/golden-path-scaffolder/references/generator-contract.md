# Generator Contract

The generator contract fixes the command shape, inputs, output tree, and guarantees before any template is written. A contract that fits in one `--help` screen is a good sign; anything larger should be split into more kinds.

## Command shape

One command per product: `<product> generate <kind> <name>`.

Examples:

- `product generate connector postgres`
- `product generate integration stripe`
- `product generate project analytics-service`
- `product generate pipeline nightly-report`

## Naming

- Kinds: lowercase, singular, one or two words (`connector`, `integration`, `project`, `pipeline`).
- Names: lowercase, kebab-case, required positional.
- Validate names against a strict pattern (`^[a-z][a-z0-9-]*$`); reject names that collide with existing directories.

## Inputs and options

1. `name` — positional, required.
2. `kind` — positional or `--kind`, required.
3. Options that change generated output — small, typed, each mapping to a documented placeholder.
4. Options that do not change output — `--output-dir`, `--dry-run`, `--yes`, `--force`.
5. Environment variables override defaults; they are inputs, never secrets to embed.
6. Secrets are never inputs to the template.

## Non-interactive mode

Generation must succeed with no prompts:

- every prompt has a default and a flag
- `--dry-run` prints the output tree and resolved inputs and writes nothing
- a missing required input fails with a nonzero exit code and a message naming the missing value
- in CI, any prompt is an error

## Idempotency

Re-running the command on an existing generated tree must either:

- produce identical output, or
- fail loudly with a diff — never silent partial output

A fresh generation is deterministic: same inputs, same tree, byte for byte.

## Re-run safety

- Generated files carry a marker: a header comment or a marker file (`GENERATED BY <product> generate <kind>`).
- Files modified since generation are detected by comparison against fresh output; they are never overwritten silently.
- Overwriting requires `--force` and prints the diff first.

## Output tree

The contract specifies the full tree:

1. the directories and files the command creates
2. the files it must never touch: existing user files, credentials, personal configuration, anything outside the output root
3. the marker format and its placement
4. exit codes: 0 success, 1 input error, 2 conflicting existing tree (define per product)

## Upgrade path

Generated projects can be regenerated:

- `generate --upgrade` or a sibling `migrate` command regenerates in place
- hand edits outside marked regions are preserved and reported
- breaking template changes ship with migration notes for existing generated projects

## Verification checklist

Verify:

- the contract fits in one `--help` screen
- the command is non-interactive end to end
- re-running on a fresh tree is a no-op or byte-identical
- re-running on an edited tree refuses to overwrite without `--force`
- the output tree is documented before templates are written
